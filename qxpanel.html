QXPANEL

使用说明

QxPanel 是部署在 Linux 服务器上的网站管理面板。安装之后用浏览器管理网站、数据库、文件、防火墙和计划任务。面板跑在 Docker 里，默认端口是 7800。网站使用你指定的端口，由面板单独拉起一份 Nginx，不会占用系统已经在 80 和 443 上运行的网站。

一键安装

服务器需要能使用 Docker。镜像是私有仓库 xiaoqiang001/qxpanel，新机器要先登录 Docker Hub：

docker login -u xiaoqiang001

一键安装：

curl -fsSL https://raw.githubusercontent.com/qx8677236-creator/panel-install/main/qxpanel-install.sh | sudo bash

已经把源码放在当前目录时，也可以：

sudo bash install-qxpanel.sh

安装脚本会做这些事：

  • 没有 Docker 时自动安装
  • 拉取镜像 xiaoqiang001/qxpanel:latest
  • 创建名为 qxpanel 的容器，开机自启
  • 面板监听 7800
  • 放行本机防火墙里的面板端口
  • 打印登录地址、账号和密码
命令作用
sudo bash install-qxpanel.sh --port 7800指定面板端口
sudo bash install-qxpanel.sh --build用当前目录源码在本机构建镜像
sudo bash install-qxpanel.sh --recreate用最新镜像重建容器，保留现有密码
sudo bash install-qxpanel.sh面板已经在运行时直接退出，不重建容器，也不改密码
云服务器还要在云厂商安全组放行 TCP 7800，以及以后每个网站使用的端口。

登录和使用

浏览器打开：

http://服务器IP:7800/bt
只打开 http://服务器IP:7800/ 会看到 404。这是入口保护，不是面板故障。

安装结束时终端会单独打印两行：账号: 和 密码:。同一份内容保存在容器内的 data/default.pl。面板已经在运行时再次执行安装，不会重建容器，也不会改密码，但会把现有账号和密码再打印一次。

界面固定为简体中文。右上角可以重启面板。更新、修复、购买、扫码登录、安装成功跳转和界面切换已经去掉。

登录密码连续错误会暂时锁定，不要反复尝试。

功能说明

左侧保留这些菜单。

首页查看服务器概况、负载仪表和网络。这里不提供软件商店、广告和远程助手。
网站创建和维护网站，支持按 IP:端口 建站、反向代理和本地备份。
数据库管理面板中的数据库。卸载面板不会停止宿主机 127.0.0.1:3306 上的另一套数据库。
Docker面板容器挂载了宿主机 Docker，用来查看和管理同一台机器上的容器。
安全只保留防火墙端口和 IP 封禁。扫描、木马查杀、入侵检测入口已经关闭。
文件在线查看、上传、编辑和删除网站目录里的文件。根目录在 /www/wwwroot/。
日志查看面板日志。软件日志入口已经去掉。
域名管理域名和证书。申请证书时，服务器需要能访问证书机构，域名也要解析到这台机器。
终端在网页里打开命令行，命令运行在面板所在的环境中。
计划任务添加按时间执行的任务。网站备份按钮本身不会创建远程存储计划。
设置修改面板密码、入口和安全选项。语言保持简体中文。

网站

创建时在域名框填写域名，或者填写 IP:端口，例如 20.187.70.213:9002。同一台服务器上，IP 相同但端口不同，可以同时存在多个网站。80 和 443 留给系统里原有的 Nginx，面板创建的网站请使用其它端口。面板端口 7800 不能当作网站端口。

创建成功后，面板会：

  • 在 /www/wwwroot/站点目录 放下网站文件
  • 写入该网站的 Nginx 配置
  • 让网站监听你填写的端口，包含 IPv6
  • 尝试在本机防火墙放行这个端口

网站详情里可以设置运行目录、伪静态、重定向和反向代理。反向代理填写完整目标地址，例如 http://95.40.120.151:5000。保存后面板会重新加载网站 Nginx，访问这个网站端口就会转到目标地址。

备份在网站列表里操作。备份文件打成 .tar.gz，保存在服务器本地。备份窗口只有「备份 / 恢复」，没有计划任务和远程网盘。备份结果用中文显示成功或失败。

删除网站时，弹窗里可以选择是否同时删除数据库、网站目录和防火墙端口。FTP 选项已经去掉。无论勾选什么，这个网站的 Nginx 配置都会删除，包括虚拟主机、反向代理、重定向和伪静态。删除最后一个自定义端口网站后，面板会关掉自己那份网站 Nginx。

网站实际怎么被访问

系统原来的 Nginx 继续监听 80 和 443。面板网站由另一份 Nginx 监听，配置文件是容器里的 /www/server/nginx/conf/qx-sites.conf，每个网站一份配置，放在 /www/server/panel/vhost/nginx/网站名.conf。

  • 访问 http://IP:网站端口/ 才会进入面板创建的网站
  • 访问 http://IP/ 仍然是系统原来的 80 端口网站
  • 面板地址始终是 http://IP:7800/bt

删除网站或卸载面板时，删掉的是这份网站配置和它的监听进程，不会重载或停止 80/443 上的系统 Nginx。

一键卸载

一键卸载从 GitHub 下载脚本并执行。脚本会先要求输入 uninstall，避免误删：

curl -fsSL https://raw.githubusercontent.com/qx8677236-creator/panel-install/main/qxpanel-uninstall.sh | sudo bash

已经下载过源码时，在源码目录执行同一份脚本：

sudo bash uninstall-qxpanel.sh

已经确认、不需要再提问时：

sudo bash uninstall-qxpanel.sh --yes

卸载会做这些事：

  1. 找出面板容器里每个网站正在监听的端口。
  2. 停止命令行里带有 qx-sites.conf 的 Nginx。系统 Nginx 的进程不带这个配置，不会被停止。
  3. 删除网站虚拟主机、反向代理、重定向、伪静态，以及 qx-sites.conf。
  4. 删除容器 qxpanel。
  5. 删除面板数据卷 qxpanel-data。登录密码和站点记录会一起消失。
  6. 收回这些网站端口和面板端口在本机防火墙里的放行。22、80、443、8000、3306 不会收回。

网站文件默认留在数据卷 qxpanel-www 里，只是不再有 Nginx 配置对外提供访问。连文件一起删除：

sudo bash uninstall-qxpanel.sh --purge
--purge 必须写在命令后面，确认时只输入 uninstall，不要输入 uninstall--purge。

云厂商安全组里手工添加的端口，脚本改不到，需要在云控制台关闭。Docker 镜像会留下，方便以后重新安装。

下面这些不会被卸载脚本改动：

  • 系统 Nginx 的 80 和 443
  • 机器上另外一套监听 8000 的服务
  • 宿主机 127.0.0.1:3306 的数据库

重新安装

卸载后再执行安装脚本即可。这是一次新的安装，会生成新的登录密码。如果卸载时没有加 --purge，原来的网站文件还在 qxpanel-www 里，但网站记录和 Nginx 配置已经没有了，需要在面板里重新建站。

已经在运行、只想换成最新镜像时：

curl -fsSL https://raw.githubusercontent.com/qx8677236-creator/panel-install/main/qxpanel-install.sh | sudo bash -s -- --recreate

现象说明
打开 http://IP:7800/ 是 404使用 http://IP:7800/bt
拉取镜像失败先执行 docker login -u xiaoqiang001
网站端口打不开检查云安全组是否放行该 TCP 端口，以及网站是否创建成功
新建 80 端口网站后公网没有变化80/443 留给系统 Nginx，请改用其它端口
再次执行安装脚本没有重置密码面板已在运行时，安装脚本不会重建容器
备份窗口是中文，文件在服务器本地备份结果是 .tar.gz，没有远程存储
第一次登录没有安装成功弹窗这是正常的。这个弹窗以前会跳到外部网站，已经去掉
